## Where a new component goes

Go down the list and stop at the first match:

1. **A token or a guideline** goes in Foundations.
2. **A piece that can't be split** into smaller parts that are useful on their own is an Element.
3. **A piece that knows about agents, runs, approvals or sources** goes in AI, however small it is.
4. **A chart or a table** goes in Data.
5. **Anything else** is a Component, and a whole screen is a Page.

> States like loading, empty or failed are stories of a component, not new components. The questions behind each step,
> with examples, are on [Composition](?path=/docs/handbook-composition--docs).

## Using the package

Install it, then add the theme to the stylesheet your app's root layout imports. The components ship with their
Tailwind classes, not compiled CSS, so your Tailwind builds them together with your own classes.

```bash
pnpm add norte-design-system
```

```css
@import "tailwindcss";
@import "norte-design-system/theme.css";
@source "../node_modules/norte-design-system/dist";
```

```tsx
import { Button, Icon } from 'norte-design-system'

export function RunButton() {
  return (
    <Button>
      <Icon name="run" /> Run agent
    </Button>
  )
}
```

**Fonts:** Norte uses Inter and JetBrains Mono. With `next/font`, expose them as the `--nt-font-sans` and
`--nt-font-mono` variables and the theme picks them up.

## Theming

Every value is a token, a CSS custom property, and components read roles, never raw colors. To adjust Norte in one
app, point a role somewhere else after the theme, and every component that reads it follows:

```css
@theme {
  --color-accent: var(--color-blue-700);
}
```

Every component also takes a `className`, merged last, so one class in your code wins over the component's own
without a fight over specificity.
